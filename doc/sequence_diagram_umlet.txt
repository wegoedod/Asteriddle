별잇기 (Byeolitgi) - Sequence Diagram UMLet Properties
=====================================================
참고: 강의자료 "0. Diagrams.pdf" 12쪽 Sequence Diagram
      Agile Modeling - UML 2 Sequence Diagrams (agilemodeling.com/artifacts/sequenceDiagram.htm)
      유스케이스 번호, 단계 번호: ssd_ip_cp2_2026f_233575 의 "6. Usecases" (UC-01 ~ UC-05)

[가장 쉬운 방법]
  같은 폴더의 sequence_diagrams.uxf 를 UMLet에서 File > Open 으로 열면 11개 다이어그램이 모두 배치된 상태로 열립니다.

[직접 붙여넣는 방법]
  ※ 반드시 시퀀스 요소에 붙여넣어야 합니다.
     "UML Activity - All in one" 요소에 붙여넣으면 순서도(둥근 박스)로 그려집니다.

  (1) 시퀀스 본체
      1. 오른쪽 위 팔레트 드롭다운에서 "UML Sequence - All in one" 선택
         ("Deprecated ..." 나 "UML Activity - All in one" 아님)
      2. 팔레트의 시퀀스 요소 아무거나 더블클릭해 다이어그램에 추가
      3. 추가한 요소 선택 → 아래 Properties 창 내용 전부 지우기 → [시퀀스] 블록 붙여넣기
      4. 요소 모서리를 끌어 권장 크기로 늘리기
  (2) 노트 (있는 다이어그램만)
      1. 팔레트 드롭다운에서 "UML Common Elements" 선택 → Note 요소 더블클릭
      2. Properties 창 내용 지우고 [노트] 블록 붙여넣기
      3. 다이어그램 오른쪽에 배치

[표기 규칙]
  - 다이어그램 하나 = 사용 시나리오 하나
      Basic Course       : 유스케이스의 기본 흐름
      Alternate Course   : 대안·예외 흐름 (번호는 유스케이스 문서의 단계 번호, 예: 7a)
      별도 다이어그램이 없는 짧은 대안 흐름은 각 다이어그램 머리글(desc)에 번호와 함께 적었습니다.
  - 프레임 이름: sd <UC 번호> <Course> - <시나리오 이름>
  - lifeline 순서 (왼쪽 → 오른쪽): 액터 → <<controller>> → <<UI>> → <<entity>>/<<utility>> → <<persistence>>
  - 밑줄 있는 이름(:GamePanel) = 객체(인스턴스)
    밑줄 없는 이름(AnswerJudge) = 클래스 (static 메서드 호출)
  - <<create>> : 객체 생성. 생성되는 객체의 박스는 생성 시점 높이에 그려짐
  - result = op(args) : 반환값을 쓰는 호출 (반환 점선 화살표 대신 표기)
  - *[조건] op() : 반복 호출,  [조건] op() : 조건부 호출
  - 메시지는 모두 실선 화살표(->>>)이고, 점선 화살표(dependency 형태)는 사용하지 않았습니다.
  - 번호 = 메시지가 발생하는 시간 순서 (PDF 예시의 "1: bark" 형식)
